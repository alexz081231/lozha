# Промпт, по которому сделана Ложа

Весь проект написала нейросеть по одному промпту — вот он целиком. Хочешь повторить эксперимент со своей моделью — открой файл в виде «Raw» и скопируй всё ниже линии.

---

Сделай с нуля сайт для совместного просмотра фильмов и прослушивания музыки с друзьями: свой маленький кинозал на своём сервере. Интерфейс на русском, название придумай сам.
Самая важная функция — загрузка видео по ссылке (YouTube, Rutube и др.). Она должна работать с первого раза и без ошибок, подробности в отдельном разделе.

## Запуск (обязательно)
- Всё запускается локально одной командой (`npm install && npm start`) на http://localhost:3000. В консоль печатается ещё и адрес в локальной сети, чтобы зайти с телефона.
- При первом запуске создаётся владелец: логин «Пользователь», пароль 12345678. Остальные регистрируются только по приглашению.
- Нужны ffmpeg/ffprobe и yt-dlp. При старте проверь, что они есть; если нет, понятно напиши, как поставить.
- Я буду тестировать с нескольких браузеров сразу: обычное окно, инкогнито, другой браузер, телефон. Голосовому чату на телефоне по локальной сети нужен HTTPS, поэтому добавь режим `npm run https` с самоподписанным сертификатом.
- Перед тем как отдать, сам запусти и пройди сценарий из раздела «Проверка». В конце дай короткую инструкцию: что и где нажимать.

## Стек
Node.js 22 + SQLite, минимум зависимостей. WebSocket для живых событий. ffmpeg/ffprobe для обработки, yt-dlp для загрузки по ссылке. Фронтенд на твой выбор, но лёгкий и быстрый, без тяжёлых UI-библиотек.

## Аккаунты и доступ
- Роли: владелец (админ) и друзья. Владелец создаёт ссылки-приглашения (одноразовые, на 7 дней), по ним регистрируются друзья.
- Пароли в scrypt или argon2, сессии в httpOnly-cookie. Защита от перебора паролей, проверка Origin у POST и WebSocket.
- Профиль: имя, аватар, смена пароля, «выйти на всех устройствах». Владелец видит друзей, кто сейчас онлайн, и может удалить друга.
- Видео и музыку сервер отдаёт только вошедшим: доступ проверяется на каждый запрос, Range-запросы работают (для перемотки).

## Загрузка видео по ссылке — главное, без ошибок
Должны скачиваться с первого раза:
- YouTube: обычные ссылки, youtu.be, Shorts, ссылки с &t= и &list= (качается только это видео, не плейлист);
- Rutube, VK Видео, Дзен, OK и любые сайты, которые знает yt-dlp;
- страницы со встроенным плеером;
- прямые ссылки на .mp4 и .m3u8.

1. yt-dlp всегда свежий. Сайты постоянно меняются, и старый yt-dlp — главная причина ошибок.
   - При старте проверь обновление: `yt-dlp -U`, а если он стоит через pip — `pip install -U yt-dlp`.
   - Всегда передавай `--js-runtimes node`: для YouTube нужен JS-движок, а Node уже есть.
2. Разбор ссылки.
   - `yt-dlp -J --no-playlist`; для страниц-подборок `--flat-playlist --playlist-end 40`. Таймаут около 60 с.
   - Качества собрать из formats: сгруппировать по высоте, взять максимальный fps, размер = видео + лучший звук.
   - 144p/240p прятать, если есть лучше. Подписи вида «1080p60», «2K», «4K60».
   - Показать превью, название, длительность и качества с размерами.
   - Если yt-dlp не понял страницу, разобрать HTML самому: `<video>`/`<source>`, og:video, ссылки на .m3u8/.mp4, iframe-плееры. Iframe отдать yt-dlp с `--referer` страницы.
3. Скачивание через yt-dlp:
   - `-f "bv*[height<=H]+ba/b[height<=H]/bv*+ba/b"`; без выбранного качества — `-f "bv*+ba/b"`;
   - `-S "res,fps,vcodec:h264,acodec:m4a"`: при равном качестве брать H.264/AAC, их играют все браузеры;
   - `--merge-output-format mkv --no-playlist --retries 10 --fragment-retries 20 --concurrent-fragments 4 --socket-timeout 30`;
   - `--newline --progress-template`, чтобы видеть проценты. Видео и звук качаются отдельно, показывать один общий прогресс;
   - `--max-filesize` по свободному месту; свой User-Agent; `--referer` для встроенных плееров;
   - готовый файл → обычная обработка (ffprobe → MP4).

   Без yt-dlp: HLS (.m3u8) через `ffmpeg -i URL -c copy`, прямые файлы потоком с проверкой каждого редиректа.
4. Готовые H.264-версии с сайта, чтобы не пересжимать.
   - YouTube отдаёт 2K/4K только в VP9/AV1, но 360p–1080p хранит и в H.264 (avc1).
   - После скачивания VP9/AV1-исходника возьми из того же списка formats версии avc1 360p–1080p с той же частотой кадров.
   - Звук AAC: оригинальная дорожка, не автодубляж и не «-drc».
   - Качай их через `--load-info-json`, без повторного разбора.
   - Перепакуй в MP4 с faststart, проверь кодек и длительность.
   - Пересжимай только то, чего на сайте нет.
5. Ошибки понятными словами, по тексту stderr yt-dlp:
   - не хватает места; сайт не поддерживается; видео под DRM; ограничение по стране; видео удалено; 403;
   - 429 → «попробуй позже»;
   - «нужен вход» или «подтвердите, что вы не бот» → владелец может загрузить cookies.txt в настройках, сервер передаёт его через `--cookies`;
   - таймаут → один автоповтор;
   - последние строки stderr писать в лог сервера.
6. Надёжность:
   - отмена убивает процессы и чистит временные файлы;
   - недокачанное после перезапуска сервера помечается ошибкой с кнопкой «Повторить»;
   - не больше 3 загрузок одновременно;
   - SSRF-защита: не ходить во внутреннюю сеть, проверять адрес и после редиректов.

## Библиотека фильмов
- Загружает только владелец. Друзья видят его библиотеку и смотрят.
- Загрузка файлов любого формата (MP4, MKV, AVI, MOV, WEBM…) и размера (десятки ГБ):
  - кусками по 8 МБ, 4–6 кусков параллельно (на телефоне меньше);
  - докачка после обрыва и после перезагрузки страницы, отмена;
  - можно перетащить файлы прямо в окно;
  - скорость показывать сглаженно, без скачков вида 30 МБ/с → 100 КБ/с.
- Обработка после загрузки:
  - ffprobe; что браузеры играют, не трогать (без потери качества); H.264/AAC → MP4 с faststart;
  - VP9/HEVC/AV1 хранить как есть, а для браузеров, которые их не играют, делать совместимую H.264-версию;
  - старые кодеки → H.264 того же разрешения и fps;
  - русская звуковая дорожка по умолчанию, текстовые субтитры → WebVTT, постер из кадра;
  - главы и лишние метаданные убирать: Safari на них спотыкается.
- Качества:
  - исходник + версии 360p/480p/720p/1080p/2K; 60 кадров остаются 60;
  - версии делаются в фоне, когда фильм уже можно смотреть: сначала лёгкие до 720p, потом тяжёлые; каждая появляется у зрителей сразу, как готова.
- Карточки фильмов со статусом в реальном времени (качается / обрабатывается / готов, проценты, какие качества уже есть). Переименование, удаление, фильтр «все / готовые / в работе». Владелец видит занятое и свободное место на диске.

## Просмотр вместе
- Комнаты:
  - открывает комнату и меняет в ней фильм только владелец;
  - один фильм — одна комната: повторное «Смотреть» ведёт в уже идущую, дублей нет;
  - в боковой панели «Смотрят сейчас»: постер, кто внутри, идёт или пауза, позиция; друзья заходят одной кнопкой или по ссылке;
  - друзья, которые сейчас на сайте, получают уведомление, когда владелец начал смотреть.
- Синхронизация:
  - состояние комнаты хранится на сервере (играет/пауза, позиция, время); часы клиента сверяются с сервером;
  - небольшое расхождение подтягивается скоростью воспроизведения, большое — перемоткой;
  - если у кого-то видео грузится, комната ждёт его и показывает это;
  - пауза и перемотка срабатывают у всех, тосты вида «Аня поставила на паузу».
- Чат комнаты с отметкой момента фильма («на 12:04»). Реакции-эмодзи всплывают поверх видео. Вкладка «Зрители» со статусами.
- Голосовой чат на WebRTC (mesh): микрофон вкл/выкл, индикатор «говорит», громкость каждого отдельно. Пока кто-то говорит, фильм немного приглушается. Работает на телефоне.

## Плеер (свой, не стандартный)
- Управление:
  - большая кнопка play, полоса перемотки с буфером и подсказкой времени, громкость;
  - полный экран (с запасным вариантом для iPhone), картинка в картинке;
  - клавиши: пробел, ←/→, f, m; на телефоне двойной тап ±10 с;
  - контролы плавно прячутся, когда мышь не двигается.
- Шестерёнка с настройками:
  - Качество: «Авто» и все версии; «Авто» на телефоне не выше 720p и на ступень ниже после двух подвисаний за минуту;
  - Масштаб: 50–200%, шаг 5%, сброс;
  - Скорость, Субтитры;
  - Статистика: разрешение, fps, битрейт, буфер, пропущенные кадры.
- Если браузер не играет кодек, плеер сам берёт совместимую версию и коротко сообщает об этом.
  - Как определить: canPlayType, ошибки декодирования и проверка, что кадры реально рисуются.
  - Safari на Mac играет VP9 сам, вплоть до 4K60; iPhone и iPad — нет.
  - Пока совместимой версии нет, показывать «Готовлю совместимую версию… N% — включится сама».
- Учитывать запрет автозапуска: запускать без звука и показывать кнопку «включить звук».

## Музыка вместе
- Раздел «Музыка»:
  - загрузка треков (MP3, FLAC, M4A, OGG, WAV) и по ссылке (YouTube, SoundCloud и др. через тот же yt-dlp, только звук);
  - обложка из файла или превью; название и исполнитель из тегов.
- Комната прослушивания:
  - общая очередь: добавить, поменять порядок перетаскиванием, удалить, следующий/предыдущий;
  - синхронное воспроизведение, тот же чат, реакции и голос.
- Мини-плеер внизу, музыка не прерывается при переходах по сайту.
- Красивый экран «Сейчас играет»: большая обложка, мягкий фон по её мотивам в ЧБ-гамме, прогресс.

## Дизайн
- Чёрно-белый (монохром). Тёмная и светлая темы: по системе плюс переключатель. Глубокий чёрный, белый, оттенки серого, эффект стекла (blur), мягкие тени, большие скругления, кнопки-пилюли.
- Движущиеся пилюли: в навигации, вкладках и переключателях активный пункт подсвечен пилюлей, которая плавно переезжает к выбранному (с лёгкой пружиной), а не перескакивает.
- Плавность — главное:
  - анимированы переходы между страницами, выезжающие листы (снизу на телефоне, по центру на компьютере), появление карточек, тосты и меню;
  - никаких резких скачков и мигания;
  - вёрстка не дёргается при загрузке (скелетоны);
  - уважай prefers-reduced-motion.
- Иконки — свой единый набор тонких линейных SVG, нарисуй сам. Своя типографика и своя сетка. Дизайн должен быть оригинальным: не копируй вёрстку, иконки и стили ни одного существующего сайта.
- Адаптив от iPhone SE до широкого монитора: на телефоне нижняя навигация, на компьютере боковая панель.

## Проверка (пройди сам перед сдачей)
1. Владелец входит и создаёт приглашение; во втором браузере по нему регистрируется друг.
2. Загрузка по ссылке — на настоящих ссылках, каждая должна скачаться и играть в Chrome и Safari:
   - обычное видео YouTube; youtu.be с ?t=; ссылка из плейлиста (&list=); Shorts;
   - видео 1080p60 и 4K (VP9);
   - Rutube, VK Видео;
   - прямая ссылка на .mp4;
   - страница со встроенным YouTube-плеером.

   Если хоть одна падает — чини, а не пропускай.
3. Загрузка файла (MP4 и MKV), дождаться версий качества.
4. Комната в двух браузерах: пауза, перемотка и скорость синхронны; чат и реакции доходят; голос соединяется.
5. Друг не может создать комнату и сменить фильм; повторное «Смотреть» не создаёт дубль.
6. Музыка: очередь и синхронное воспроизведение в двух браузерах; трек по ссылке с YouTube.
7. Мобильная вёрстка и обе темы без поломок.
